# Kubernetes Secrets Management Best Practices

Managing secrets in Kubernetes is a critical aspect of maintaining secure cloud-native applications. Default Kubernetes secrets are base64-encoded (not encrypted), making proper secrets management essential for production environments.

## The Problem with Default Secrets

Kubernetes secrets by default have several limitations:

- **Not encrypted at rest**: Secrets are only base64-encoded in etcd
- **No rotation**: Manual secret rotation is error-prone
- **Access control**: RBAC can be complex to configure correctly
- **GitOps challenges**: Storing secrets in Git is a security risk

## Modern Solutions

### Sealed Secrets

Sealed Secrets by Bitnami allows you to encrypt secrets and store them safely in Git:

```yaml
apiVersion: bitnami.com/v1alpha1
kind: SealedSecret
metadata:
  name: mysecret
  namespace: production
spec:
  encryptedData:
    password: AgBy3i4OJSWK+PiTySYZZA9rO43cGDEq...
```

### External Secrets Operator

External Secrets Operator integrates with external secret stores like AWS Secrets Manager, HashiCorp Vault, and Azure Key Vault:

```yaml
apiVersion: external-secrets.io/v1beta1
kind: ExternalSecret
metadata:
  name: database-credentials
spec:
  secretStoreRef:
    name: aws-secrets-manager
    kind: SecretStore
  target:
    name: db-secret
  data:
    - secretKey: password
      remoteRef:
        key: prod/database/password
```

## Best Practices

1. **Always encrypt secrets at rest**: Enable encryption at rest in etcd
2. **Use external secret stores**: Leverage AWS Secrets Manager, Vault, etc.
3. **Implement secret rotation**: Automate secret rotation policies
4. **Apply the principle of least privilege**: Use RBAC to restrict access
5. **Audit access**: Enable audit logging for secret access

## Implementing Vault with Kubernetes

HashiCorp Vault provides enterprise-grade secrets management:

```bash
# Install Vault using Helm
helm repo add hashicorp https://helm.releases.hashicorp.com
helm install vault hashicorp/vault \
  --set "server.ha.enabled=true" \
  --set "server.ha.replicas=3"
```

### Vault Agent Injector

The Vault Agent Injector automatically injects secrets into pods:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: app
  annotations:
    vault.hashicorp.com/agent-inject: "true"
    vault.hashicorp.com/role: "myapp"
    vault.hashicorp.com/agent-inject-secret-config: "secret/data/myapp/config"
spec:
  containers:
    - name: app
      image: myapp:latest
```

## Encryption at Rest

Enable encryption at rest in your Kubernetes cluster:

```yaml
apiVersion: apiserver.config.k8s.io/v1
kind: EncryptionConfiguration
resources:
  - resources:
      - secrets
    providers:
      - aescbc:
          keys:
            - name: key1
              secret: <BASE64_ENCODED_SECRET>
      - identity: {}
```

## Conclusion

Proper secrets management is non-negotiable for production Kubernetes deployments. Use external secret stores, implement encryption at rest, and automate rotation to maintain a strong security posture.
