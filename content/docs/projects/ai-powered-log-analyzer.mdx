## Overview

LogInsight AI is an intelligent log analysis platform that uses Large Language Models (LLMs) and vector databases to help SRE teams quickly identify issues, find root causes, and get suggested remediation steps—all through natural language queries.

## The Problem

Traditional log analysis faces several challenges:

- **Volume**: Modern applications generate millions of logs daily
- **Complexity**: Logs are unstructured and hard to parse
- **Time-consuming**: Finding relevant logs requires complex queries
- **Context loss**: Correlation across services is manual
- **Expertise required**: Deep domain knowledge needed to interpret logs

## Solution Architecture

### High-Level Design

**Architecture Flow:**

1. **Log Sources** → Ship logs to **Ingestion Layer**
2. **Ingestion Layer** → **Processing Pipeline**
3. **Processing Pipeline** → Stores data in both:
   - **Vector Database** (for semantic search)
   - **Time-Series DB** (for temporal queries)
4. **LLM** + **RAG Pipeline** retrieves context from both databases
5. **User Query** → **RAG Pipeline** → **Natural Language Response**

### Technology Stack

- **Backend**: Python 3.11, FastAPI
- **LLM**: OpenAI GPT-4, Ollama (local fallback)
- **Vector Database**: Pinecone
- **Time-Series DB**: ClickHouse
- **Processing**: Apache Kafka, Flink
- **Observability**: Prometheus, Grafana
- **Frontend**: React, TypeScript
- **Infrastructure**: Kubernetes, AWS

### 2. Vector Embedding Generation

Convert logs to embeddings for semantic search:

```python
from langchain.embeddings import OpenAIEmbeddings
from langchain.text_splitter import RecursiveCharacterTextSplitter
import pinecone

class LogEmbedder:
    def __init__(self):
        self.embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
        self.text_splitter = RecursiveCharacterTextSplitter(
            chunk_size=500,
            chunk_overlap=50
        )

        # Initialize Pinecone
        pinecone.init(
            api_key=os.getenv("PINECONE_API_KEY"),
            environment="us-west1-gcp"
        )
        self.index = pinecone.Index("log-embeddings")

    def embed_log(self, log_entry):
        # Create searchable text
        text = f"""
        Service: {log_entry['service']}
        Level: {log_entry['level']}
        Message: {log_entry['message']}
        Error Type: {log_entry.get('error_type', 'N/A')}
        """

        # Generate embedding
        embedding = self.embeddings.embed_query(text)

        # Store in vector DB
        self.index.upsert(
            vectors=[{
                'id': log_entry['id'],
                'values': embedding,
                'metadata': {
                    'timestamp': log_entry['timestamp'],
                    'service': log_entry['service'],
                    'level': log_entry['level'],
                    'message': log_entry['message'][:1000]  # Limit size
                }
            }]
        )

        return embedding

embedder = LogEmbedder()
```

### 3. RAG Pipeline for Query Processing

Implement Retrieval-Augmented Generation:

```python
from langchain.chat_models import ChatOpenAI
from langchain.chains import ConversationalRetrievalChain
from langchain.vectorstores import Pinecone
from langchain.prompts import PromptTemplate

class LogAnalyzer:
    def __init__(self):
        self.llm = ChatOpenAI(
            model_name="gpt-4-turbo-preview",
            temperature=0.2
        )

        self.vectorstore = Pinecone.from_existing_index(
            index_name="log-embeddings",
            embedding=OpenAIEmbeddings()
        )

        # Custom prompt for log analysis
        self.prompt_template = """
        You are an expert SRE analyzing application logs. Based on the following log entries:

        {context}

        User Question: {question}

        Provide:
        1. A clear explanation of what's happening
        2. Likely root cause
        3. Suggested remediation steps
        4. Related logs to investigate

        Be specific and actionable. Reference log timestamps and services.
        """

        self.qa_chain = ConversationalRetrievalChain.from_llm(
            llm=self.llm,
            retriever=self.vectorstore.as_retriever(
                search_kwargs={"k": 10}
            ),
            return_source_documents=True
        )

    def analyze(self, query: str, chat_history: list = []):
        response = self.qa_chain({
            "question": query,
            "chat_history": chat_history
        })

        return {
            "answer": response['answer'],
            "source_logs": [
                {
                    "timestamp": doc.metadata['timestamp'],
                    "service": doc.metadata['service'],
                    "message": doc.metadata['message']
                }
                for doc in response['source_documents']
            ]
        }

analyzer = LogAnalyzer()
```

### 5. Automated Anomaly Detection

Detect unusual patterns automatically:

```python
from sklearn.ensemble import IsolationForest
import numpy as np

class AnomalyDetector:
    def __init__(self):
        self.model = IsolationForest(
            contamination=0.1,
            random_state=42
        )
        self.is_trained = False

    def extract_features(self, logs):
        # Feature engineering
        features = []
        for log in logs:
            features.append([
                log['error_count'],
                log['response_time'],
                log['requests_per_minute'],
                log['unique_errors'],
                log['error_rate']
            ])
        return np.array(features)

    def train(self, historical_logs):
        features = self.extract_features(historical_logs)
        self.model.fit(features)
        self.is_trained = True

    def detect_anomalies(self, current_logs):
        if not self.is_trained:
            raise ValueError("Model not trained")

        features = self.extract_features(current_logs)
        predictions = self.model.predict(features)

        # -1 indicates anomaly
        anomalies = [
            log for log, pred in zip(current_logs, predictions)
            if pred == -1
        ]

        return anomalies
```

**Solution**: Implemented tiered model strategy:

- GPT-4 for complex analysis
- GPT-3.5 for simple queries
- Local Ollama model for development/testing

### Challenge: Context Window Limitations

**Solution**: Smart log summarization and chunking strategy to fit within token limits

### Challenge: Real-time Performance

**Solution**: Hybrid architecture with pre-computed embeddings and caching layer
